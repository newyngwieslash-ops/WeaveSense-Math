# 09 授权、内容投影、数据模型与契约冻结（W0：DEV-005 至 DEV-008）

本文件把 W0 设计项冻结为当前实现的书面基线。接口细节以 [03-接口契约.md](03-接口契约.md) 为准，迁移以 [07-部署-迁移-回退-恢复.md](07-部署-迁移-回退-恢复.md) 为准，本文件只写跨接口的规则、撤销影响、投影矩阵、实体与保留策略。标“待确认”的条目是需要机构或产品负责人拍板的默认值，未拍板前按本文默认执行。

## 1 角色与资源授权（DEV-005）

### 1.1 身份解析

| 身份 | 解析方式 | 作用范围 |
| --- | --- | --- |
| 教职（teacher、reviewer、org_admin） | 平台会话 + X-Workspace-Id；必须是该工作区成员，且在该工作区租户有 active、未到期、租户级或与当前工作区一致的教育角色绑定 | 本租户本工作区 |
| 租户所有者、管理员 | 平台成员角色 owner、admin | 只获得管理权（角色、预算、同意、账本、策略），不因此获得 teacher 或 reviewer |
| 学生 | 平台会话 + X-Edu-Tenant；该租户有 active student 绑定 | 不获得任何工作区成员身份或 viewer 权限 |
| 数学服务 | HMAC 签名（入站事件） | 只写事件收件箱 |
| 签名取件链接 | 短时签名 + 产物受众检查 | 单个产物 |

所有教育表 FORCE RLS，按 app.tenant_ids 隔离；数据库层隔离之外，服务端再按下表做资源级检查。

### 1.2 逐操作授权（按资源族）

| 资源族 | 读 | 写 | 额外条件 |
| --- | --- | --- | --- |
| 题目、题目修订、分析与讲解作业、讲解修订、变式题组、编辑 | 本工作区教职 | teacher | 作业受预算与并发准入；编辑绑定 baseHash |
| 审核 | 本工作区教职 | reviewer；或机构策略 self_allowed 时作者本人 teacher；second_reviewer 时作者不可自审 | 绑定精确 lesson hash；有阻断错误不得批准 |
| 发布 | 本工作区教职 | teacher | 只发布 approved、hash 一致、无阻断错误的修订；发布不可变 |
| 班级、任课 | org_admin 看本工作区全部；teacher 只看自己任课的班 | 建班 teacher 或 org_admin；加任课 org_admin 或租户管理员 | 他人班级按不存在处理（404） |
| 邀请、名单导入、名单行、选课、退班、延期、任务、迁移、重评分、教师作答视图、求助、学情 | 该班任课 teacher 或 org_admin | 同左 | 布置与迁移检查来源权利；迁移与重评分需 confirm |
| 同意记录、机构策略写、角色、预算写、账本、成本 | 租户 owner、admin 或 org_admin | 同左 | 理由必填的写操作写审计 |
| 来源资产 | 本工作区教职 | teacher 或管理员 | 撤回后不可改权利 |
| 课程与对齐 | 本工作区教职 | 本工作区教职 | 对齐的讲解修订须在本工作区 |
| 内容事故 | 本工作区教职 | teacher 或管理员 | blocking 解决须人工审核的修正发布 |
| 学生作业、学习状态、作答、提示、自测、预测、图形事件、求助、复习、进度、重评分通知 | 本人 | 本人 | 每次请求检查：student 角色、active 选课、任务受众（班级与延期）、任务 active、同意（机构策略要求时）、来源允许学生使用 |
| 产物取件 | 教师预览：本工作区教职；学生产物：满足上一行条件的学生 | 无 | 签名短时有效；产物撤回后立即失效 |

全路由越权扫描 E44 枚举全部 /api/edu 路由，验证匿名、他租户教师与管理员、学生访问教师路由都不能读写受害者资源；新增路由自动纳入。

### 1.3 撤销与撤回的影响

| 事件 | 立即生效范围 | 保留 | 恢复方式 |
| --- | --- | --- | --- |
| 教育角色撤销或到期 | 下一次请求起失去该角色的全部操作；进行中的作业继续由 worker 在租户上下文结算 | 该用户创建的修订、发布、审核记录、审计 | 管理员重新绑定（role.renew） |
| 任课撤销 | 该班不可见 | 班级、任务、作答 | 重新指派任课 |
| 邀请码撤销 | 未使用的码立即无效 | 已加入的学生不受影响 | 新建邀请 |
| 名单行撤销或重发 | 旧码立即无效 | 已认领行不能撤销，只能走退班 | 重发生成新码 |
| 学生退班 | 该班全部任务、产物链接立即不可用；邀请码与名单码不能恢复选课（403） | 作答、提示、求助记录保留供教师查看 | 教师重新选课（待确认流程） |
| 学生角色撤销 | 该租户全部学生接口 403 | 同上 | 管理员重新绑定 |
| 同意撤回 | 该学生全部学生接口 403 CONSENT_REQUIRED；名册标注 | 既有记录保留，不再新增 | 重新记录同意（需证据编号） |
| 任务撤回 | 学生不可见、不可作答 | 作答保留 | 新建任务 |
| 内容事故 blocking | 发布与讲解修订 withdrawn，active 任务 suspended，变式题组 withdrawn，学生产物撤销（已签发链接 403/404） | 作答保留，影响清单快照 | 修正发布后迁移任务，按需重评分 |
| 来源撤回或到期 | 不能再布置、迁移、生成变式；学生读取依赖该来源的内容按不存在处理 | 内容与作答保留 | 新来源或替换内容 |
| 机构策略改为 second_reviewer | 之后的审核按新策略；已批准修订不回溯 | 审核记录 | 无 |

## 2 内容投影与答案政策（DEV-006）

| 字段或媒体 | 教师与审核员 | 课堂投屏 | 学生学习（答案未开放） | 学生学习（答案已开放） | 独立自测 | 导出 |
| --- | --- | --- | --- | --- | --- | --- |
| 题面、图形 | 是 | 是 | 是 | 是 | 是 | 未提供 |
| 讲解步骤、字幕、图形标签 | 是 | 是（教师预览产物） | 只到不泄露答案的步骤；字幕与标签按学生投影重新渲染 | 是 | 否 | 未提供 |
| 最终答案、答案键、判分参数 | 是 | 是 | 否（API、HTML、字幕、标签、缓存、媒体均不含） | 是 | 否，提交后按政策 | 未提供 |
| 验证证据与状态分层 | 是 | 否 | 否 | 否 | 否 | 未提供 |
| 提示 | 是 | 否 | 按层级解锁，提示不含答案 | 是 | 否 | 未提供 |
| 判分结果 | 全部学生 | 否 | 本人：正确、错误、无效、待人工 | 同左 | 交卷后 | 未提供 |
| 重评分 | 新旧结果与理由 | 否 | 本人新旧结果与固定说明，不含教师理由 | 同左 | 否 | 未提供 |
| 账本、成本 | 管理员 | 否 | 否 | 否 | 否 | 管理员 CSV（账本报表） |

规则：

1. 答案政策取值 teacher_release（默认）、after_due、after_submission；释放判定在服务端，只在前端隐藏不算实现（E6 E13 E19）。
2. 学生产物是单独渲染的学生投影，不是教师产物加遮罩；教师预览产物不向学生签发。
3. 旧版迁移：任务迁移到修正发布后，旧作答保持原结果，重评分另行发起；迁移不沿用变式题组；答案释放时间沿用原任务。
4. 曝光口径：学情面板与成本报告按选课学生计数；名册只显示选课编号、显示名、学号（假名）与同意状态，不显示联系方式。
5. 导出视图：发布导出（学生版默认、教师版）与学习报告已实现（E53）：来源须 allowExport，学生版还须 allowStudent，按受众裁剪并列出未包含字段。跨机构复用：平台没有任何跨租户复制路径（FORCE RLS），allowCrossOrg 只记录权利；若将来开放跨机构共享，必须先检查该标志（Q21）。

### 3.2 版本协议

1. 题目修订确认后不可变；修改产生新修订（revision 递增）。
2. 讲解修订由作业产生，lesson_hash 覆盖学生可见内容与答案键；编辑产生子修订（parent_lesson_revision_id），审核绑定精确 hash。
3. 发布一经产生不可变，只能 withdrawn；修正走新修订、新发布、任务迁移。
4. 并发写用 hash 或 version 比对，冲突 409（REVISION_CONFLICT、VERSION_CONFLICT）。
5. 迁移顺序：v68 至 v97，只新增表与列（例外见上），版本保护拒绝旧二进制启动；每个版本的内容与回退见 07。
6. 实体关系（主链）：机构策略与角色绑定 → 班级（任课、选课、邀请、名单条目）；来源资产 → 题目 → 题目修订 → 数学作业（阶段、产物、作业事实）→ 题解修订 → 讲解修订（编辑、人工输入、审核）→ 发布 → 任务（延期、迁移、变式题组）→ 作答与学习记录（提示、自测、复习、预测、图形交互、求助、重评分）；内容事故关联发布与任务，复盘与修订通知挂在事故上；预算、提醒、账本异常与支持成本挂在租户与作业上。本节表格由 CI（check-edu-handover.py）对照 models_edu.go 的全部 edu_ 表检查，新增表未写入本表即失败。

### 3.3 保留策略（机构确认后才清理）

| 数据 | 默认 | 建议（待机构确认） |
| --- | --- | --- |
| 审计、账本、阶段、作业事实 | 永久保留 | 至少 3 年（财务与争议） |
| 学生作答、提示、求助、预测、图形交互 | 保留至机构删除请求 | 学年结束后 1 年，按机构书面请求匿名化 |
| 讲解修订与产物 | 保留；课程 retainRevisions 只记录意图 | 未发布且超过保留数的修订可清理产物字节，元数据保留 |
| 入站事件收件箱 | 保留 | 90 天 |
| 名单认领码 hash | 保留 | 认领或过期后 30 天清空 hash |

实现（DEV-106，v89）：机构确认前上表与“临时 7、作答图 90、学习记录 180、备份 30 天”都只是建议值，不清理任何数据；机构管理员核对天数并写理由后确认（有上下限，写审计），清理先预览影响再执行，平台每日只对已确认租户执行。审计、账本、阶段与作业事实不在清理范围。

## 4 Schema、API 与事件契约（DEV-008）

1. Schema：Problem、Solution、Validation（math_state 为 verified、partially_verified 或 failed；每项检查记 passed、failed 或 undetermined 及其 scope 与证据，evidence_levels 单列；超时或无法判定记 undetermined，不等于无解；数值抽样只在其 scope 内成立；教学与呈现的人工审校单列，不计入数学验证）、Lesson、Artifact、Job（状态与阶段）、Usage（阶段结算与用量行）以及统一错误 `{code, data, msg}` 与业务码（INPUT_AMBIGUOUS、REVISION_CONFLICT、VALIDATION_FAILED、POLICY_REVOKED、RIGHTS_RESTRICTED、PARAMETER_LIMIT、BUDGET_EXCEEDED、RATE_LIMITED、CONSENT_REQUIRED、VERSION_CONFLICT），见 03。
2. 教育业务 API：03 逐路由列出角色与字段；E44 保证注册路由与授权一致。
3. MCP 工具：七个平台适配工具（启动、等待、读取），见 03 第 1 节。
4. 事件：出站作业事实 outbox `GET /api/edu/jobs/:id/events?after=N`（job.accepted、状态事实、cancel_requested、结算等，按 seq，单次至多 200）；入站数学服务事件 `POST /api/edu-math-events`（HMAC 签名、4 KiB 上限、事件 ID 去重）。
5. 兼容策略：字段只增不删；新增枚举值在 07 标出对旧二进制的影响；错误码只增不改义；破坏性变更须新路径或新版本号，并在 03 写明迁移期。
