# 07 部署配置、迁移、回退与恢复

## 配置项
| 变量 | 位置 | 说明 |
| --- | --- | --- |
| FLOW_MATH_SERVICE_URL | Go 后端 | 未设置时不注册 /api/edu，也不启动 worker（功能整体关闭） |
| FLOW_MATH_SERVICE_KEY | Go 后端 | ≥32 字节；与 MATH_SERVICE_KEY 相同；通过密钥管理分发 |
| FLOW_MCP_INTERNAL_TARGETS | Go 后端 | 可选。精确内网 MCP 目标 JSON 数组（端点、工具清单、凭据引用），格式错误时启动失败；未设置时网关保持只连公网 https。见 03“Agent 侧数学工具” |
| EDU_ARTIFACT_URL_KEY | Go 后端 | 可选；签名链接密钥，默认从服务密钥派生 |
| EDU_MATH_JOB_BUDGET_MICRO | Go 后端 | 单作业预留上限，默认 120000 |
| EDU_BUDGET_TZ | Go 后端 | 机构月预算的自然月时区，默认 Asia/Shanghai |
| EDU_LEDGER_RECONCILE_EVERY | Go 后端 | 定时账本对账间隔（Go 时长），默认 24h，最短 5m，off 关闭 |
| MATH_SERVICE_KEY、MATH_DATA_DIR、MATH_LISTEN | 数学服务 | 数据目录需持久卷；监听地址仅限内网 |
| MATH_EVENT_URL | 数学服务 | 可选；平台入站地址 `<后端>/api/edu-math-events`（内网）。设置后服务以 MATH_SERVICE_KEY 签名推送作业事件，至少一次投递，失败退避最长 60 秒；未设置时平台按 worker 拉取 |

数学服务只依赖 Python 3.12 与 sympy 1.13.3；不得注入任何平台密钥（阶段子进程以空环境运行）。

## 迁移 v89（edu_retention_policies_v89）
- 新增 edu_retention_policies（每租户一行的保留期确认，DEV-106），FORCE RLS，tenant_id 为主键。只新增表，不改旧数据。CurrentSchemaVersion = 89。旧二进制遇到 89 会拒绝启动；回退时可保留该表，旧平台不会执行清理。
- 清理是“只做状态迁移”规则的第二个例外：机构确认保留期后，离班超过学习记录保留期的学生在该班任务中的学习记录与认领的名单条目被物理删除。这是保留义务本身的要求；只有机构管理员写明理由确认后才会执行（未确认的租户什么也不删），先可预览影响，账本、用量与审计不在范围内，离班记录保留以便核对，每次清理写只含计数的审计。失败或取消作业的过期产物只在平台撤销，数学服务存储中的字节暂未删除。

## 恢复演练与重放日志（DEV-122）
- 目标：普通业务 RPO 不超过 24 小时、RTO 不超过 4 小时；账本与确认作答 RPO 目标 5 分钟。每日 pg_dump（daily.sh）只满足前者；后者需要部署方开启 PostgreSQL WAL 连续归档（archive_mode、archive_command 写入独立存储）并定期做时间点恢复，应用无法替部署方验证，DEV-122 因此保持进行中。
- 恢复日志：设置 `EDU_RESTORE_JOURNAL=/路径/edu-restore.jsonl`（独立持久卷，不与数据库同盘，按分钟级同步到备份存储）。平台在事务提交成功后追加一行并 fsync，记录内容撤回（阻断事故）、撤回同意申请、删除申请，只含租户、对象与申请编号、类型、申请人类别、操作人与时间，不含原因、证据与正文。追加失败写日志 `restore journal append failed`，此时该动作只能依赖库内标记。未配置时重放接口返回 409。
- 演练脚本：`deploy/flow/backup/restore-drill.sh <源库URL> <空的演练库URL> [输出目录]`，调用 backup.sh 与 restore.sh 做真实备份与恢复，核对清单，输出备份时间点与备份、恢复耗时；目标库非空或与源库相同时拒绝执行。CI 的 A18 作业每次运行。本地 200 张表约 8 秒备份、8 秒恢复。
- 恢复步骤：1）停止学生访问（取消 FLOW_MATH_SERVICE_URL 或在入口拦截）；2）restore.sh 恢复并核对清单，记下备份时间点；3）每个机构管理员（或运维在维护窗口内代为操作）调用 POST /api/edu/restore/replay `{since}` 预览，核对 items 后加 `confirm: true` 执行；superseded 条目表示学生在申请后被重新接纳，人工核对后处理；4）POST /edu/data-requests/replay（confirm）；5）POST /edu/retention/run（confirm）；6）POST /edu/metrics/collect；7）恢复学生访问。备份点之后新增的作答、修订与发布无法从日志恢复，属于 RPO 内的损失，需通知教师。
- 演练记录：每季度至少一次在演练库上跑 restore-drill.sh 与重放预览，记录耗时与差异条目数。类生产环境（含对象存储与日志卷）的整体演练尚未做。

## 恢复
- 作业状态以平台 edu_math_jobs 为准；worker 每 2 秒同步非终态或结算未完成的作业。
- 平台重启：worker 继续同步，按 seq 单调采纳，阶段结算按 (job, stage) 唯一，不会重复扣费。
- 数学服务重启：服务从数据目录恢复作业并按检查点续跑。
- 提交结果未知：作业为 reconciliation_required，预留保持；调用 POST /api/edu/jobs/:id/reconcile 或等 worker 自动对账。
- 数据目录丢失：已入库产物元数据仍在平台，但正文需要重新生成（接入对象存储后解决）。
