# 07 部署配置、迁移、回退与恢复

## 配置项
| 变量 | 位置 | 说明 |
| --- | --- | --- |
| FLOW_MATH_SERVICE_URL | Go 后端 | 未设置时不注册 /api/edu，也不启动 worker（功能整体关闭） |
| FLOW_MATH_SERVICE_KEY | Go 后端 | ≥32 字节；与 MATH_SERVICE_KEY 相同；通过密钥管理分发 |
| FLOW_MCP_INTERNAL_TARGETS | Go 后端 | 可选。精确内网 MCP 目标 JSON 数组（端点、工具清单、凭据引用），格式错误时启动失败；未设置时网关保持只连公网 https。见 03“Agent 侧数学工具” |
| EDU_ARTIFACT_URL_KEY | Go 后端 | 可选；签名链接密钥，默认从服务密钥派生 |
| EDU_MATH_JOB_BUDGET_MICRO | Go 后端 | 单作业预留上限，默认 120000 |
| EDU_BUDGET_TZ | Go 后端 | 机构月预算的自然月时区，默认 Asia/Shanghai |
| EDU_LEDGER_RECONCILE_EVERY | Go 后端 | 定时账本对账间隔（Go 时长），默认 24h，最短 5m，off 关闭 |
| MATH_SERVICE_KEY、MATH_DATA_DIR、MATH_LISTEN | 数学服务 | 数据目录需持久卷；监听地址仅限内网 |
| MATH_EVENT_URL | 数学服务 | 可选；平台入站地址 `<后端>/api/edu-math-events`（内网）。设置后服务以 MATH_SERVICE_KEY 签名推送作业事件，至少一次投递，失败退避最长 60 秒；未设置时平台按 worker 拉取 |

数学服务只依赖 Python 3.12 与 sympy 1.13.3；不得注入任何平台密钥（阶段子进程以空环境运行）。

## 合并到 WeaveSense-Math：画布执行迁移 v68 改为 v84
- 用户在 WeaveSense-Math 上的行业研判提交把 canvas_workflow_execution 迁移编为 v68，与 edumath 已在 Flow main 上发布的 v68（edu_math_workbench_v68）冲突。集成时 edumath v68 至 v83 保持不变，画布迁移改为 v84（校验和 sha256:canvas-workflow-execution-v84，内容仍为对 flow_canvas_workflow_executions 与 flow_canvas_monitor_run_usage 的幂等 AutoMigrate 加 FORCE RLS）。CurrentSchemaVersion = 84。
- 风险：任何已经用 Math main 旧版本启动过的数据库，schema_migrations 里 v68 记录的是画布迁移的校验和，新二进制会以“数据库迁移 68 校验和不一致”拒绝启动。处理：确认该库没有 edu_* 表后，人工删除 schema_migrations 中 version 68 的记录再启动（v68 至 v84 会依次执行，画布表 AutoMigrate 幂等）；或者用新库。全新数据库与只运行过 Flow 版本的数据库不受影响。
- 迁移工具 migrate-sqlite-postgres 的表清单补上 flow_canvas_workflow_executions 与 flow_canvas_monitor_run_usage。
- Loom Engine 新增迁移 0023：flow_collection_windows.interval_seconds 去掉非空约束。cron 调度没有 interval_seconds，原 0021 的非空约束会让整轮调度失败。

## 容器镜像名（WeaveSense-Math，2026-10-27 起）
- 原镜像名 open-ai-canvas-backend、open-ai-canvas-web、open-ai-canvas-yingce-agent 在 GHCR 上归属另一个仓库，本仓库的 GITHUB_TOKEN 无权推送（permission_denied: read_package）。按用户决定，本仓库的发布工作流改为推送：
  - ghcr.io/newyngwieslash-ops/weavesense-math-backend（amd64 与 arm64）
  - ghcr.io/newyngwieslash-ops/weavesense-math-web（多架构）
  - ghcr.io/newyngwieslash-ops/weavesense-math-yingce-agent（多架构）
- 标签：每次 main 推送都会打 sha-<完整提交>、sha-<前 7 位>；当该提交仍是 main 最新提交时再打 latest；推送 v* 版本标签时打版本号（去掉 v）。2026-10-27 15:56（UTC+8）发布后实测：三个包均可匿名拉取（不登录取得匿名令牌后请求 latest 清单返回 200），即为公开，跟随本公开仓库；拉取不需要 docker login。若以后改为私有，需先用带 read:packages 的令牌 docker login ghcr.io。
- 未改动的引用：docker-compose.yml、docker-compose.local.yml、docker-compose.build.yml、docker-compose.server.yml 中的 open-ai-canvas-*:local 和 open-ai-canvas-*:server 是本机构建标签，与 GHCR 无关。docker-compose.deploy.yml 的 yingce-agent 回退镜像、scripts/install-*.sh、host-updater 默认仓库以及 backend/internal/hostupdate 的镜像名仍指向上游 ddcat-ai/open-ai-canvas 的发布。用本仓库镜像部署时，需要在 .env 中显式设置 CANVAS_BACKEND_IMAGE、CANVAS_WEB_IMAGE、CANVAS_YINGCE_AGENT_IMAGE（带 digest），不要用 host-updater 自动升级，除非后续把 hostupdate 的镜像名也改为可配置。
- 数学服务（services/math-service）不在任何镜像中，需单独以 python -m mathsvc.server 运行（见上方配置项）。

## 回退
1. 功能回退：取消 FLOW_MATH_SERVICE_URL 并重启后端，/api/edu 与 worker 不再加载；数据保留。
2. 代码回退：回滚到更早版本的二进制。v68 的表保留不删除（无破坏性），重新升级时迁移幂等。
3. 不要手工删除 edu_* 表；涉及学生记录与账本，删除属于不可逆操作，需要书面批准。

## 恢复
- 作业状态以平台 edu_math_jobs 为准；worker 每 2 秒同步非终态或结算未完成的作业。
- 平台重启：worker 继续同步，按 seq 单调采纳，阶段结算按 (job, stage) 唯一，不会重复扣费。
- 数学服务重启：服务从数据目录恢复作业并按检查点续跑。
- 提交结果未知：作业为 reconciliation_required，预留保持；调用 POST /api/edu/jobs/:id/reconcile 或等 worker 自动对账。
- 数据目录丢失：已入库产物元数据仍在平台，但正文需要重新生成（接入对象存储后解决）。
