# 07 部署配置、迁移、回退与恢复

部署方须提供的条件（WAL 连续归档与时间点恢复、类生产恢复演练、日志卷与备份保留、外部探针与告警渠道、数据库直连控制、部署配置人工核对、对象存储与资产域名）汇总见 11 第 9 节 U9、U10、U12。

## 配置项
| 变量 | 位置 | 说明 |
| --- | --- | --- |
| FLOW_MATH_SERVICE_URL | Go 后端 | 未设置时不注册 /api/edu，也不启动 worker（功能整体关闭） |
| FLOW_MATH_SERVICE_KEY | Go 后端 | ≥32 字节；与 MATH_SERVICE_KEY 相同；通过密钥管理分发 |
| FLOW_MCP_INTERNAL_TARGETS | Go 后端 | 可选。精确内网 MCP 目标 JSON 数组（端点、工具清单、凭据引用），格式错误时启动失败；未设置时网关保持只连公网 https。见 03“Agent 侧数学工具” |
| EDU_ARTIFACT_URL_KEY | Go 后端 | 可选；签名链接密钥，默认从服务密钥派生 |
| EDU_MATH_JOB_BUDGET_MICRO | Go 后端 | 单作业预留上限，默认 120000 |
| EDU_BUDGET_TZ | Go 后端 | 机构月预算的自然月时区，默认 Asia/Shanghai |
| EDU_LEDGER_RECONCILE_EVERY | Go 后端 | 定时账本对账间隔（Go 时长），默认 24h，最短 5m，off 关闭 |
| MATH_SERVICE_KEY、MATH_DATA_DIR、MATH_LISTEN | 数学服务 | 数据目录需持久卷；监听地址仅限内网 |
| MATH_EVENT_URL | 数学服务 | 可选；平台入站地址 `<后端>/api/edu-math-events`（内网）。设置后服务以 MATH_SERVICE_KEY 签名推送作业事件，至少一次投递，失败退避最长 60 秒；未设置时平台按 worker 拉取 |

数学服务只依赖 Python 3.12 与 sympy 1.13.3；不得注入任何平台密钥（阶段子进程以空环境运行）。

## 升级准入与事故处置（DEV-126）
- 代码升级准入：CI 后端检查在 go test 之后运行 `.github/scripts/edu-upgrade-admission.py`，按本次 PR 相对基线的变更路径确定受影响领域（求解与验证、渲染模板、模型与智能体工具及 Skill 包、课程规则、价格与成本、教学、权限与迁移），要求对应套件在本次运行中真实执行并通过，否则检查失败、不能合并。未归类的教育路径、无法确定变更集以及发布流水线（workflow_call）一律要求全部套件。报告 edu-upgrade-admission.json 随 go-test-timings 产物保存，步骤摘要中有逐项表。数学服务自身的 pytest 由 Math service tests 检查负责，同为合并必需。
- 配置升级（不经过上面的准入，需人工）：改 FLOW_PRICE_BOOK 价格簿、平台模型选择、数学服务镜像标签或渲染版本前，先在预发环境用同一配置跑一次后端检查（至少 E66、E67 与费用套件），记录结果；价格簿只影响新受理的作业（受理时冻结）。上线后观察 /edu/admin 运行观测与对账一个周期。出现问题按“回退”一节处理。
- 事故处置顺序：1）定位：在发布版上开阻断事故，先不带 confirm 看影响（任务、班级、学生、作答），需要时用作业 trace 查生成链路；2）止损：确认撤回（学生立即不可见），范围更大时按题族或渲染版本暂停；3）修订：在事故修订上编辑，重新人工审核（继承审核不算），暂停解除后发布修正版；4）通知：以修正版关闭事故，系统给仍在使用旧版本任务的每位现任任课教师发修订通知，教师迁移任务后通知自动关闭，也可确认已知；5）复盘：在机构管理“事故复盘”中写根因、发现途径、纠正措施与后续事项，写后不可修改，不写学生姓名与联系方式。阻断事故关闭后未复盘的会一直列在待复盘中。
- 已知缺口：学生不单独收到修订通知，只在任务迁移后看到新版本；配置升级的准入是人工步骤。

## SQLite 事务锁（平台修复，E86）
- database.Open 打开 SQLite 时经 SQLiteDSN 追加 `_txlock=immediate`，默认连接串为 `file:<路径>?_busy_timeout=5000&_journal_mode=WAL&_foreign_keys=on&_synchronous=NORMAL&_txlock=immediate`。服务端、migrate-schema、migrate-sqlite-postgres、reseed-logical-model-sources、migrate-logical-model-families、migrate-channel-model-price-tiers 都走这一路径。
- 原因：默认的延迟事务先取读锁，第一次写时才升级为写锁；升级时若另一连接持有写锁，SQLite 直接返回 database is locked，不经 busy_timeout 等待（等待会造成死锁）。BEGIN IMMEDIATE 在事务开始时就取写保留锁，排队由 busy_timeout 处理。
- 例外：连接串已显式指定 _txlock 的保持原值；`mode=ro` 只读连接串（migrate-sqlite-postgres 的源库）不追加，因为只读文件上 BEGIN IMMEDIATE 会失败。
- 只读事务的代价：mattn/go-sqlite3 忽略 sql.TxOptions 的 ReadOnly 与隔离级别，repository/payment_export.go 的两个只读导出事务在 SQLite 上也会在事务期间持写保留锁，其他写事务按 busy_timeout（5 秒）排队。这两个事务只做有界查询，持锁时间短；WAL 模式下事务外的读与其他连接的读不受影响。PostgreSQL 部署不受影响。若以后出现长时间只读事务，应改为不开事务读取，或单独用 mode=ro 连接。
- 回退：回滚该提交即恢复延迟事务，数据与表结构不受影响。
