## 4 操作手册

### 4.1 教师
1. **首页**（/edu/home）：待办（待审核讲解、求助、修订通知）、我的班级、我的讲解、示例题与演示班级（处处标为示例）。
2. **备课**（/edu/author）：按五步完成。
   1. 题目与参数：选择题族并填写参数，或粘贴题目文字后逐项确认题意。
      可选：展开“题目图片”，选择来源后上传 PNG 或 JPEG（不超过 10 MB），在原图上拖动框选一道题（或使用整张图）生成单题图，保存题目后点“关联到本题”。图片只有老师看得到，系统会清除拍摄位置等元数据；系统不识别图片文字，题面仍需自己录入并确认。
   2. 数学分析：提交后返回作业编号，可离开页面；结果区分已证明、数值抽样、超时未定等状态，超时不代表无解。
   3. 讲解与审核：查看讲解与图形，按审核清单逐项确认后通过。审核绑定当前修订与 hash；修改会产生新修订，需要重新审核。
   4. 举一反三自测题组（可选）：变式只改数字；数量不足时如实显示原因。
   5. 布置到班级：选择班级、答案开放政策与截止时间。已发布内容不可修改，修改请新建修订后迁移任务。
3. **课堂**（/edu/teach）：学情分布、求助（按优先级）、作答记录、运行中的任务；可撤回发布或迁移任务，系统先显示影响范围。
4. **修订通知**：内容事故解决后首页出现通知，确认已读；把任务迁移到新修订后通知自动关闭。
5. **错误提示**：页面只显示中文说明与错误码，不显示服务端原文；遇到 PAUSED 或 PAUSE_CHECK_UNAVAILABLE 时等待机构管理员解除或系统恢复。

### 4.2 学生
1. **我的学习**（/edu/learn）：只能看到已选课班级中已布置给自己的作业。
2. 作业页：静音逐步讲解（无有声模式）、图形探索前先做预测、提交答案（题组每题只能提交一次）、提示与求助、复习与学习记录。
3. 答案按老师设定的政策开放；开放前页面、接口、图形标签与链接都不携带答案（硬约束 2）。

### 4.3 机构管理员
1. **机构设置**：审核策略（self_allowed 或 second_reviewer）、讲解编辑审核继承、班级与名单导入（拒绝手机号、邮箱、身份证号）、监护同意证据编号录入。
2. **运营面板**：运行观测、交付成本、账本对账、预算与公平限流、暂停与回退、事故复盘、数据申请、限时运维授权、保留策略确认。
3. 使用真实学生前必须完成授权、同意、隐私与数据隔离前置要求（硬约束 8）。目前这些前置要求都未完成。

## 8 平台层发现（不在教育模块范围，交由平台负责人）
1. 已修复（E86，平台修复 PR，用户授权）：生产 SQLite 连接串（backend/internal/database/database.go）原先未设置 `_txlock=immediate`，并发写事务在读锁升级为写锁时直接返回 database is locked，不经 busy_timeout 等待。现在所有经 database.Open 打开 SQLite 的路径都追加 `_txlock=immediate`（保留原有参数；显式 _txlock 与 mode=ro 只读连接串不变），说明见 07。
2. 已修复（E87，平台修复 PR，用户授权）：画布工作流后台执行器的错误此前被吞掉，已受理（admitted）的执行记录会一直停留，代码注释提到的恢复清扫器并不存在。现在执行器错误写日志并以错误码记入执行记录；恢复清扫器在启动时与每分钟运行一次，只把从未派发任何工作的执行重新排队（最多 3 次），其余一律按受控清理关闭，未知结果的付费调用转入对账，从不重跑，见 07。
3. 已修复（E88，平台修复 PR，用户授权）：loom-engine 字幕服务（services/loom-engine/workers/subtitle/server.py）原先用 preexec_fn 设置子进程资源限制。preexec_fn 在 fork 与 exec 之间运行 Python，父进程有线程时（asyncio 在默认线程池上解析 DNS）不安全，可能使子进程在 exec 前死锁而父进程在超时保护之外等待，数学服务曾因此出现故障。现改为与数学服务相同的思路：子进程 exec 后先由一个极小的引导程序设置 RLIMIT_FSIZE（2 MiB）与 RLIMIT_CORE（0），再 exec 真正的命令；新会话仍由 start_new_session 建立，环境变量与限制不变。字幕测试已加入 CI。
